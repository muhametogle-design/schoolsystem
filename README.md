# NE-EMIS — National Education Management Information System

A multi-tenant, cloud-based Education Management Information System reference
implementation. It models persistent **NE-SID / NE-TID / NE-MID / NE-CID**
identifiers, campus-isolated (RLS) read/write, a four-phase ingestion/audit/
aggregation/state-control pipeline, and cryptographic record freezing for
campus dean approvals.

> This repository contains the **database schema, services, API, locking
> engine, seed tooling, tests and deployment assets**. Everything is designed
> to run on PostgreSQL 15+ and FastAPI.

## 2. Core identifiers

| Identifier | Table.column | Scope |
|---|---|---|
| **NE-SID** | `students.ne_sid` | Global student PK across K-12 → higher education |
| **NE-TID** | `teachers.ne_tid` | Global teacher PK linking credentials, payroll, background checks |
| **NE-MID** | `managers.ne_mid` | Global manager/dean PK + Ed25519 verification key |
| **NE-CID** | `course_sections.ne_cid` | State curriculum bound to a campus section/classroom |

All identifier columns are generated by `BEFORE INSERT` triggers
(`app.gen_ne_sid`, `app.gen_ne_tid`, `app.gen_ne_mid`, `app.gen_ne_cid`) and
are never rewritten.

---

## 3. Four-phase pipeline

```
Phase 1  Clerks           -> real-time format validation + local writes
Phase 2  Deans            -> review summaries + Ed25519 signature lock (freezes rows)
Phase 3  Overnight engine -> centre state registries (student/teacher) + KPIs
Phase 4  State admins     -> regional KPIs, vacancy tracking, automated payouts
```

The locking trigger `app.enforce_record_lock()` prevents ordinary
`UPDATE`/`DELETE` on a frozen record. A state-controlled unlock with a
counter-signature is possible but preserves the immutable lock history.

## 5. Quick start (local)

### 5.0 Skip straight to the UI (no DB needed)

```bash
make install
make demo          # serves the interactive dashboard at http://localhost:5000
```

The `/` route renders a live, clickable dashboard (Overview, Student Registry,
Teacher Governance, Attendance, Audit & Lock, Aggregation, Funding & Payroll)
backed by an in-memory demo service. Real DB-backed integration uses the same
API contract via Postgres.

### 5.0 Clone the repo on Windows (if you don't have it locally)

Your current folder `C:\Users\EastG` has no `schoolsystem` folder yet — that's
why `.\scripts\...` isn't recognised. Get the code first:

```powershell
# Go to your user folder (or wherever you want it)
cd C:\Users\EastG

# Clone the repo
git clone https://github.com/muhametogle-design/schoolsystem.git

# Enter it and take the working branch (this is where all scripts live)
cd schoolsystem
git checkout arena/01a043e9-schoolsystem
git pull

# Verify
.\scripts\check_env.ps1
```

> If `git` isn't recognised, install Git for Windows
> (https://git-scm.com/download/win) or use GitHub Desktop to clone
> `muhametogle-design/schoolsystem` to `C:\Users\EastG`.

## 7. Important security notes

- **RLS** is enabled on every tenant table; `campus_id` comes from the
  transaction-local `set_config('neemis.campus_id', ...)`.
- **National IDs** are stored as salted SHA-256 hashes; **bank accounts** are
  AEAD-encrypted at rest via `bytea`.
- **Dean locking** requires a real Ed25519 public key tied to `managers`.
- **State unlock** is only permitted for roles in `STATE_UNLOCK_ROLES`.

See [`SECURITY_AND_RLS.md`](SECURITY_AND_RLS.md) for the full threat model and
operational notes.
