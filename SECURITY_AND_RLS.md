# NE-EMIS Security & RLS Design

## 1. Tenant isolation

- Each tenant row contains `campus_id`.
- The API sets transaction-local Postgres settings:
  - `neemis.campus_id`
  - `neemis.role`
  - `neemis.user_id`
- RLS policies on tenant tables force:
  - `campus_id = app.current_campus_id()`
  - OR `role IN ('state_admin','system','aggregator')`
- Central `central.*` tables are readable only by state roles.

## 2. Identifier immutability

`NE-SID`, `NE-TID`, `NE-MID`, `NE-CID` are generated by `BEFORE INSERT`
triggers and not exposed through application `insert` statements. They are
never mutated by the API.

## 3. Record-locking threat model

### Normal flow
1. Clerk submits attendance / grades / payroll.
2. Dean reviews the campus summary.
3. Dean signs `canonical_envelope` with their Ed25519 private key.
4. `record_locks` stores the signature + payload hash.
5. DB trigger `enforce_record_lock` raises `55000` on later update/delete.

### Attack: forged lock
A forged signature cannot pass `verify_envelope()` because the public key is
stored on the `managers` row.

### Attack: modified record after lock
The freeze trigger blocks `UPDATE`/`DELETE`. A state-controlled unlock is
logged and requires a counter-signature and a role in `STATE_UNLOCK_ROLES`.

## 4. Sensitive data

- `national_id_hash` — salted SHA-256 (never plaintext).
- `bank_account_encrypted` — AEAD-encrypted `bytea`.
- `managers.verification_public_key` — Ed25519 SPKI (public, not secret).

## 5. RLS policy details

The DDL applies tenant policies over the list:

```
students, enrollments, student_mobility, transfer_clearances, majors,
classrooms, course_sections, course_enrollments, transcripts, exam_sheets,
attendance, incident_reports, truancy_marks, teachers,
teacher_qualifications, teacher_certifications, teacher_assignments,
teacher_payroll_profiles, teacher_background_logs, teacher_exit_records,
payroll_entries, record_locks, pending_locks, ingestion_jobs
```

## 6. Operational hard requirements

- Use TLS/SSL in front of the API in production.
- Never ship `certs/demo_dean_private.pem` to production.
- Rotate dean keys with `key_version` and `key_revoked_at`.
- Set all roles via app service, never allow client-supplied `role`/`campus_id`.
